# 单校试运行与证据采集包

更新：2026-10-16。适用对象：项目负责人、档口负责人、数据负责人。所有 CSV 是空模板，不是已完成调研、授权、训练或收益证明。

## 先准备什么

1. 学校/档口许可、数据用途与期限、原件保管位置；仅引用授权编号，不把个人信息写进代码库。
2. 学校、档口、菜品编号；售价、单位成本、计量单位（首版为份）、餐次。
3. 经授权的历史台账：日期、菜品、餐次、制作/售出/剩余、收入、天气；不要把停业、缺失和售罄后的观测销量当作正常零需求。
4. 当餐本菜品可分配的原料折算份数、总产能、最小批量、首批开始准备时间、开餐与结束时间、单次提前期。共享原料和设备不能在多个菜品中重复分配。

## 用户每天做什么

| 环节 | 准备与输入 | 得到与核对 |
|---|---|---|
| 首次建档 | 学校授权引用、档口、菜品、价格、成本、负责人 | 学校/档口/菜品编号；仍为声明待核验 |
| 导入台账 | 使用网页导出/下载的 CSV 字段；预览后填写来源与许可 | 成功/拒绝行、源文件 SHA-256、原始行号；不自动证明来源真实 |
| 营业前预测 | 日期、具体餐次、菜品、预计天气、考试/活动 | 历史截止、样本数、来源、模型版本、需求参考 |
| 现场计划 | 填写库存、产能、批量、提前期和同日时段 | 计划首批/补餐/总量/缺口、警告、留档编号；可重新读回 |
| 人工确认 | 核对计划和数量，填写调整原因 | 执行确认；超过最近计划上限须重新生成现场计划 |
| 闭餐回填 | 实际制作、售出、优惠售出、剩余、收入、异常 | 数量守恒校验、预测关联、经营复盘；实际超做应如实记录，不改写事实 |
| 周复盘 | 原件、问题与使用记录 | 预测偏差与执行偏差分开；不从销量直接推导因果收益 |

全日预测不能直接生成现场计划，必须拆分早餐/午餐/晚餐。时段不跨日。首批不能按时完成时返回零计划；无补餐窗口只给首批。补餐数量是条件参考，不预留库存、不下发制作命令。旧计划不可随新参数静默改写。

## 数据为什么这样选，如何证明可靠

| 数据 | 选择理由 | 必须保存的证据 | 不能证明什么 |
|---|---|---|---|
| 同菜品、同餐次历史台账 | 直接对应当前份数决策；跨菜品/餐次混用会改变口径 | 原件、提供方、授权用途、哈希、行号、首次可用/修订时间、数量核对 | 有文件或哈希不等于真实；售罄销量不是未满足需求 |
| 预测前已发布的天气预报 | 经营前可获得，适合作为候选外生特征 | 预报发布时间、适用日、地域、快照 | 历史实况不可代替当时未知的预报 |
| 学校校历、活动与停业记录 | 区分考试、活动和非营业日 | 官方或负责人确认、发布时间、适用范围 | 城市节日不能自动等同本校活动 |
| 现场库存/产能快照 | 把预测需求约束为当班能做的数量 | 录入责任、时间、分配口径、计划编号 | 不是实时库存系统，不能证明跨菜品共享资源最优 |
| 公开需求数据 | 验证方法和程序、比较简单基线 | 原发布页、许可、字段定义、目标性质、划分与脚本 | 不是河北试点，不可把缩放销量换算成现场份数收益 |
| 项目内演示数据 | 展示页面与接口闭环 | 明确构造/测算标签、隔离库 | 不支持访谈数量、商业收入、减损效果或模型校园准确率 |

原件由授权数据负责人在独立受控目录保管，代码库只保留脱敏引用和哈希。对原件修改生成新版本，禁止直接覆盖。`authorization_check.csv` 和 `original_file_register.csv` 由两名责任人核对后签署；未核验记录保持待核验。平台当前没有完整的原件托管或人工核验审批系统，模板不替代这些能力。

## 本地试运行

在项目根目录设置 `FOODWISE_ADMIN_PASSWORD`（至少10位），然后执行：

```powershell
$env:FOODWISE_ADMIN_PASSWORD = Read-Host '本地管理员密码' -MaskInput
.\gradlew.bat bootRun --args='--spring.profiles.active=local-pilot --server.address=127.0.0.1'
```

默认文件库为 `data/pilot/foodwise-pilot`，演示经营种子和远程 AI 关闭，认证开启。显式仅使用 local-pilot，勿叠加 demo/local-persistent。首次打开建档页；历史不足时按提示补数据。数据库内容和账号不应提交 Git。V2 仍含历史参考校历、V15 含待核验来源登记，它们不属于真实学校资料；空库指经营主数据和交易为空，不承诺所有参考表为空。

## 停机备份与隔离恢复

先正常结束应用并确认数据库不再被占用。下面目录名为示例，请使用新的备份与恢复目录：

```powershell
.\scripts\backup-restore-h2.ps1 -Action backup -Source .\data\pilot -Target .\data\backups\pilot-20261016
.\scripts\backup-restore-h2.ps1 -Action restore -Source .\data\backups\pilot-20261016 -Target .\data\restore-check\pilot-20261016
$env:FOODWISE_LOCAL_PILOT_DB_URL='jdbc:h2:file:./data/restore-check/pilot-20261016/foodwise-pilot;MODE=MySQL;DATABASE_TO_LOWER=TRUE'
.\gradlew.bat bootRun --args='--spring.profiles.active=local-pilot --server.address=127.0.0.1'
```

脚本拒绝已有目标、运行中/有锁数据库和不匹配的备份哈希。源目录只允许一个 .mv.db；备份只复制数据库，不打包原件、模型和密钥。恢复后逐项读回档口、菜品、台账、预测与计划，保存结果；复制成功不等于业务恢复完成。MySQL 备份、并发、账号最小权限和生产容量须独立验收。

性能入口 `python scripts/measure-local-api.py --output output/local-api-performance.json`：仅允许本机地址，顺序 GET，3次预热+30次采样，记录 p50/p95；认证环境通过 `FOODWISE_TEST_PASSWORD` 传入密码。结果不代表线上并发或预测速度。

## 现场验证怎样开展

先授权，再影子运行；建议1校、2档口、6—10道稳定菜品、午餐起步，属于拟议规模。每次操作记录完成耗时、错误、帮助次数和采纳原因；不采集无关学生身份。每日核对缺失、守恒、单位、重复、售罄及修订；异常由负责人处理，不静默填零。

试运行收益须在现场方批准后预先固定对照策略、营业日分组、成本与缺货口径，并按营业日聚类分析；记录活动、价格、人手、售罄和停业混杂。没有随机或合适对照时，只报告描述性变化。时间相关性、样本不足或关键组退化时延期，不以100行或28日自动认定充分。

模板位于本目录；训练原始字段继续使用 `modeling/templates/`，网页运营 CSV 与科研 CSV 是不同入口，必须逐字段转换并复核。

## 重复本轮工程验收

运行 `gradlew test bootJar`、前端 `npm run typecheck` 和 `python -m unittest discover -s modeling/tests -v`。Python需要兼容的 NumPy/pandas/scikit-learn/LightGBM，不得以跳过候选训练测试代替通过。本轮使用 Python3.12.4、NumPy1.26.4、pandas2.2.2、scikit-learn1.4.2、LightGBM4.6.0；原默认用户包与全局包混用曾报 ABI 冲突，原失败日志保留。

浏览器脚本 `scripts/validate-landing-browser.py --confirm-disposable` 仅用于构造验收：先在 `.local-validation/landing-20261016/test-password.txt` 保存临时验收密码（该目录已忽略），以该密码在本机18096端口启动**新的空文件库**、仅激活local-pilot，再运行脚本。需本机已有 Python Playwright及Chromium。脚本拒绝非本机地址和非空菜品库，写入构造学校/台账，保存截图、业务快照及浏览器结果。不得用于真实试运行库。停机前保存快照；正常重启相同库后运行 `python scripts/verify-pilot-readback.py --stage restart`；停机备份/恢复到新目录并启动恢复库后运行 `--stage restored`，两者均比较相同业务快照。临时密码、数据库和来源原件均不进入发布包。
