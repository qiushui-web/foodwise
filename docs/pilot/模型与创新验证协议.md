# 模型与创新验证协议

本协议是待真实材料进入后的执行设计，不是已经取得的学术或校园效果。工程证据以本轮测试日志为准。

## 三个可检验的主张

1. 时点回放：按预测时刻可见的修订生成特征，未来补录不会改变旧预测输入。以保留快照、来源关联及未来修订反例测试举证；这项属于工程机制，是否构成学术新颖性仍需正式文献与同类系统比较。
2. 约束决策：原始需求与库存/产能/批量/时段分离，负责人得到能解释的计划与缺口。以零库存、批量、超时和人工确认的实测流程举证；当前不解决多菜品共享资源的优化。
3. 可核查的人机协作：预测模型给数量，规则层限制动作，人确认并回填，大模型仅辅助解释。AI关闭时主流程必须可用；不把提示词/API接入单独称为原创算法。

## 训练冻结顺序

- 来源先人工核验：原始台账、许可用途、地域、单位与首次可用时间；构造、派生、缩放数据分开。
- 固定实体键与目标：同学校/档口/菜品/餐次的售出份数；供给受限样本单列，不能当真实需求标签。
- 按日期固定 fit → tune → calibration → test；同一日期不跨集合。预测快照冻结 cutoff/watermark/revision IDs；校准标签必须在首次测试预测前已可用。
- 基线先行：同星期均值、滚动均值/EWMA；仅在 fit/tune 比较受限 LightGBM-L1 与残差候选。固定种子、预算和特征，不用 test 选模型。
- calibration 只估计80%/90%有限样本残差区间；不足以支持目标分位点则拒绝输出。test 只报告一次，已看过的公开后段属于探索集。时间漂移下不作无条件覆盖保证。
- 消融使用相同切分：去天气、去日历、去趋势、去分组；另做留档口/菜品或新增时间尾段确认。关键组退化时保留简单基线。

保存输入/脚本/模型/特征 SHA-256、切分清单、种子、依赖版本、训练日志、逐行预测、指标、运行时间与资源、复现命令。`modeling/scripts/25_campus_admission.py` 负责准入，26负责时点特征与候选/校准/测试产物，27负责模型包，28负责修订与区间检查；使用各脚本 `--help` 获取当前参数。当前 `training_ready=false` 和 `production_approved=false` 门槛不得绕过。

## 报告什么才有说服力

先给简单基线，再给候选绝对 MAE（份），同时给逐菜品偏差、缺货/剩余损失（成本由档口确认）、供给受限子组、区间覆盖和宽度、延迟与资源。改善百分比须展示分母、样本和日期；公开缩放销量指标不与校园份数横比。营业日聚类置信区间需在数据足够且方案冻结后计算，不能将菜品×日期当独立重复。

Python-Java须对同一模型、特征与快照逐字段、逐行对照；启动清单一致不等于模型科学或校园有效。模型存在本机只减少远程调用依赖，是否加速须同硬件、同负载、同输入测量；模型大小、特征查询、认证、数据库和页面资源同样影响耗时。当前网页规则预测与本地LightGBM演示不能合称“已训练河北校园大模型”。

## 上线门槛与失败处理

来源和授权、日期划分、独立校准、实体确认、Java一致性、影子运行、现场方批准分别签署。任一门槛未通过则不发布校园效果、不自动切换模型。候选输给基线、漂移、校准不足或数据异常时保留基线/停止建议，保留不利结果和人工处理记录。
