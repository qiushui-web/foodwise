## 0 一句话

从"用一个派生标签模型做预测演示"，改成"**用可追溯的数据给出可对账的备餐建议，并由一个不许乱说话的参谋智能体解释它**"。

## 1 三个病灶（都有据）

| 病灶 | 证据 | 后果 |
|---|---|---|
| **数据不成立** | 训练用 2,600 行派生标签（源数据没有销量）；真实台账仅 14 天，有效独立样本 n≈14 | 任何精度结论都站不住 |
| **模型与数据错配** | 部署链路 24 维 LightGBM，其中 6 维是写死常量；14 天数据喂不出训练分布 | 真正起作用的是校准偏移，模型是装饰 |
| **因果不可说** | 台账 基线期=前 7 天、干预期=后 7 天，采纳率 0%→100%，高温只出现在干预期 | 7.7pp 无法归因，一旦被追问就崩 |

结论：**问题不在"再找一个数据集"，在于把"证明链"重新设计一遍。**

## 2 数据底座：三层，各管一件事

| 层 | 内容 | 回答什么 | 证据等级（对外写法） |
|---|---|---|---|
| **L1 真实公开** | ZHAW 大学食堂 60 天销售、芬兰学校食堂 154 天备餐过剩、德国烘焙连锁 2.7 年订量/售出/剩余、FreshRetailNet 断货标注 | 方法在真实世界成不成立 | "在真实食堂/门店数据上的外部效度" |
| **L2 校准仿真器** | 90 天 × 7 菜品，字段与站点台账逐列同构 + 一列 `demand_qty` 真值 | 需要多少天才够、误报率多少、方法值多少 | "仿真器生成，参数校准自 4 个公开来源" |
| **L3 现场采集** | 35 天 × 2 档口（建议/对照），5 个字段 | 在中国校园到底有没有效 | "单校试点"（未做则不许写） |

**硬规则**：L2 永不进网站线上库，文件名带 `sim_`，CSV 内 `synthetic=true`；`demand_qty` 只许用于评估，出现于特征即测试失败。

## 3 建模：三层，砍掉一切撑不住的复杂度

### 3.1 需求区间层（部署链路）

```
q̂_τ(d,t) = Median_{同菜品同星期近 4 周}(sold) · s_d + offset_τ
s_d      = 池化尺度（菜品内 MAD 向全局收缩，κ=20）
offset_τ = 保形校准分位数（留一天交叉，LODO）
```

- **LightGBM 降级**：只保留为 L1 上的离线对照，证据页标注"未进入部署链路"。
- **ACI 保留但默认关闭**：只在检出漂移（连续 5 天残差同号）时启用，避免小样本下过度反应。
- 特征从 24 维砍到 **8 个**，且全部可从台账直接算：同菜品近 4 个同星期售出中位数、近 7 日中位数、近 3 日趋势、天气、考试周、活动、售价/成本、上周期执行偏差。

### 3.2 决策层

```
q = q̂_τ + α_d（制作损耗/固定扣减）
q = 按最小批次 5 取整，截断 [0, min(产能, 可用原料)]
输出：建议量 + 区间 + 后悔上界 + 成本敏感性带
```

- 成本参数（售价、成本、折价率、残值、缺货惩罚）从"代码常量"改为**页面可输入 + 场景默认值**，并标注"未经验证的情景假设"。
- 后悔上界用 L1 的 regret 分布给出，不承诺具体减损比例。

### 3.3 归因层

- 现状：描述性前后对照，**必须**带"时间与天气混杂"声明。
- 升级路径：只有 L3 的并行对照（两档口同期）才能谈因果；在此之前，报告只能写"观察到差异"。

### 3.4 明确不做

不做时序大模型、不做 BSTS 全 MCMC（实测覆盖率 82.5%，反而更差）、不让 LLM 生成任何数值。

## 4 经营参谋智能体：先做"不会说谎的"，再谈"更聪明的"

### 4.1 定位

不是"AI 预测"，是**能对账的参谋**：把模型已经算出来的东西讲清楚，把用户没问到的风险指出来，把不该答的问题挡回去。

三层能力，按此顺序实现：

| 能力 | 做什么 | 例子 |
|---|---|---|
| **解释** | 讲清建议量怎么来的 | "建议 100 份 = 分位 82 + 制作损耗 0 + 补餐 18；临界比 0.886，缺货成本高于剩余成本" |
| **追问** | 给定"如果…会怎样"的对比 | "若成本按 6 元算，建议量下降 7 份，后悔上界从 12.3 元升到 15.1 元" |
| **复盘** | 把当日实际与建议对账 | "建议 100、实际备 92、售 88、剩 4；执行偏差 −8 份，占建议量 8%" |

### 4.2 输入输出契约（先立契约，再谈模型）

```json
POST /api/v1/assistant/advice
{
  "date": "2026-07-20", "dishId": 1,
  "question": "为什么建议 100 份？",
  "context": {
    "plan":    { "center": 82, "sigma": 9.4, "q": 100, "interval": [64, 97], "criticalRatio": 0.886 },
    "cost":    { "price": 13.0, "unitCost": 5.2, "underage": 10.14, "overage": 1.3 },
    "history": [ { "date": "...", "prepared": 83, "sold": 80, "leftover": 3 } ],
    "modelVersion": "2026.10.27-interval-v1",
    "calibrationSha256": "1047da73…6cdf"
  }
}
```

```json
{
  "answer": "建议 100 份：分位 82 份上浮到按成本算的临界比 0.886 对应量，再按最小批次 5 取整。区间 64–97 份，建议量高于上界 97，因为缺货成本约为剩余成本的 7.8 倍。",
  "citations": [
    { "type": "plan", "ref": "q=100, center=82, interval=[64,97]" },
    { "type": "cost", "ref": "underage=10.14, overage=1.3" },
    { "type": "ledger", "ref": "2026-07-20/dish=1/prepared=83" }
  ],
  "suggestedAction": null,
  "refusal": null
}
```

### 4.3 拒绝边界（可测，不是口号）

| 场景 | 行为 | 返回码 |
|---|---|---|
| 问"明天能卖多少份" | 只给区间与建议量，不给点预测承诺 | `NO_POINT_FORECAST` |
| 问"用了你们是不是能省 30%" | 明确拒绝，说明只可复现方法 | `NO_EFFECT_CLAIM` |
| 问"这个菜是不是不新鲜/能不能吃" | 转食品安全责任，拒绝判断 | `OUT_OF_SCOPE_FOOD_SAFETY` |
| 问与经营无关 | 拒绝并给出可问范围 | `OUT_OF_SCOPE` |
| 数据不足以回答 | 说"历史不足 7 天，置信度低" | `INSUFFICIENT_HISTORY` |

### 4.4 关键决策：先做确定性参谋，不接大模型

**理由**：本地没有可控模型、评审现场可能断网、数值一致性必须 100%。所以第一版是**规则化参谋**——模板 + 数值槽位填充 + 引用定位，全部可测、可复现、零幻觉。接口和契约先立住，未来把后端换成 LLM 时，契约与测试都不用改。

### 4.5 评测（50 条固定问答集 × 5 类）

| 指标 | 阈值 | 怎么测 |
|---|---|---|
| 数值一致率 | **100%** | 回答中每个数字必须出现在 context 允许列表 |
| 引用准确率 | ≥ 90% | 每条 citation 能指回具体字段/台账行 |
| 越界拒绝率 | **100%** | 20 条越界问题全部返回 refusal |
| 无关拒答 | 100% | 10 条无关问题全部 `OUT_OF_SCOPE` |
| 平均响应 | < 200 ms | 本地基准 |

## 5 评估口径与四条红线

**指标**：regret/百份、剩余率、缺货率、执行偏差（预测精度降为中间指标）。

**红线**：

1. 仿真数据不进线上库，图题写"仿真器生成"；
2. 公开数据指标只能出现在"外部效度"一节；
3. 智能体回答中的数字必须与引擎输出逐一致，禁止自行推算；
4. 无并行对照，不写因果；无现场采集，不写减损。
