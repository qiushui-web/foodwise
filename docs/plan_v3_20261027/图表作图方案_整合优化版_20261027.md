**绘制状态（2026-10-28）**：本文件所列 20 张示意图**已全部绘制并插入正文**，占位框全部删除。图源为 Python 拼 SVG 再截图：`figs_v3/gen_lib.py` 提供画布、箭头、文本框等元件，`figs_v3/fig_*.py` 逐图组装，`render_all.py` 批量出图。实际取值：画布宽 500 单位（＝13.2 cm），导出 PNG 约 301 dpi 并保留同名 SVG，配色与下表一致。逐图说明保留在本文件第二节之后，作为改图依据。

## 一、总则

**用途**：本文件是计划书全部示意类图表的绘制说明书。正文中 20 处图位已按本文件编号逐张绘制并替换（2026-10-28；图源与脚本见《使用说明》的图表工作流一节）；另有 11 张真实界面截图（图3-2、图3-3、图3-5、图5-4、图A-1～图A-7）直接沿用，不在本文件绘制范围内。

**画布与导出**

| 项 | 要求 |
|---|---|
| 画布 | 正文插图统一按 13.2 cm × 6.0～9.5 cm 设计（版心 15.7 cm，左右各留 1.2 cm 余量） |
| 导出 | PNG，300 dpi，白底，无透明通道；同名 .svg 一并保留以便改字 |
| 字体 | 中文黑体（标题级 10.5 pt / 说明级 9 pt），西文与数字 Times New Roman |
| 字号下限 | 导出后不小于 8 pt，保证 A4 打印可读 |
| 线宽 | 外框 1.0 pt，主箭头 1.0 pt，辅助线 0.5 pt（虚线用 2-2 间距） |
| 圆角 | 统一 2 mm；同一张图内圆角必须一致 |

**配色（全篇统一，最多三色 + 两级灰）**

| 语义 | 色值 | 用法 |
|---|---|---|
| 主色（平台/本期） | `#1F4E79` | 由平台产生的结果、当前方案 |
| 辅色（数据/输入） | `#2E75B6` | 台账、模型产物、指标 |
| 强调（人工确认/风险） | `#C00000` | 人工节点、拒绝分支、缺口与红线 |
| 中性灰 | `#7F7F7F` | 外部系统、非本期范围 |
| 浅底 | `#F2F2F2` | 分组底色、注释区 |

**通用绘图纪律**

1. 一张图只讲一件事，标题写在图题里，**图内不重复图题**。
2. 箭头必须有方向语义：实线＝数据/流程，虚线＝确认/授权/降级，红色＝异常或拒绝分支。
3. 每个框内的文字不超过 3 行、每行不超过 12 字；超出的信息移到图注或正文。
4. 图内出现的数字必须与正文一致，不得出现正文没有的数字。
5. 不出现品牌 Logo、装饰性插画、渐变与阴影；不使用 3D 效果。
6. 禁止把“规划/待验证”画成既成事实：未实现环节用虚线框或斜纹填充，并在图内标注“规划”。

## 三、逐图绘制说明

### 图1-1 短保餐品的剩余与缺货双重损失

- **类型**：因果框图（左右对照）
- **内部模块**：中心节点“备餐量决策”；左链 4 框（备餐过量→闭餐剩余→折价／报损→毛利损失）；右链 4 框（备餐不足→高峰售罄→流失销售→口碑损失）；下方 3 个约束条（保质期以小时计／就餐时段集中／单餐菜品有限）
- **数据流向**：由中心节点向左右各发散一条链，箭头单向、末端为“损失”；三条约束以细虚线指向中心节点，表示共同作用于决策
- **标注文字**：中心“备餐量决策（每天一次）”；左端“剩余损失”；右端“缺货损失”；底部“两者并存，不是二选一”
- **箭头逻辑**：实线主链（因果）；虚线为约束条件（作用于决策，非流程）
- **绘图重点**：左右必须完全对称、层级数相同，视觉上体现“同一决策的两侧代价”；不要画成时间顺序流程；末端两个“损失”用同一色深，强调等价而非取舍

### 图2-1 营业日四个决策时点与可用信息

- **类型**：时间轴（横轴＋上下双层标注）
- **内部模块**：横轴 5 个刻度（备餐→开餐→高峰→闭餐→复盘）；轴上 4 个节点圆点；节点上方信息框（历史台账／当日天气与课表／实时销量／剩余与报损）；节点下方输出框（建议量与首批／补餐触发／优惠与下架／复盘口径）
- **数据流向**：时间向右推进；上方信息“流入”节点，下方输出“流出”节点
- **标注文字**：四个节点分别标“T1 备餐前”“T2 开餐”“T3 高峰”“T4 闭餐后”；虚线域标注“仅用事前信息”“事后才可知”
- **箭头逻辑**：上层箭头向下入节点（信息约束），下层箭头自节点向下出（动作）。两层箭头方向相反，形成“信息进、动作出”
- **绘图重点**：必须用一条纵向虚线把 T3 之前与之后分开，突出“不使用未来信息”；四个节点的间距不等距时需在图注说明

### 图2-2 三类角色与信息流向

- **类型**：角色关系图（三主体＋中心平台）
- **内部模块**：左“档口负责人”、右上“食堂运营方”、右下“学生”、中心“食刻有数平台”；每条连线上挂字段标签
- **数据流向**：档口→平台（台账、成本与约束参数、实际结果）；运营方→平台（准入授权、共享资源额度、异常处置）；平台→学生（餐品与优惠信息）；学生→平台（预约、核销、反馈）
- **标注文字**：四条实线分别标“台账／成本／结果”“授权／额度”“餐品／优惠”“预约／核销”；两条虚线标“确认”“监督”
- **箭头逻辑**：实线＝数据，虚线＝确认与授权；学生方向为双向但粗细不同（平台发布细、学生回传更细）
- **绘图重点**：四个框的视觉权重必须区分——平台用主色实底，三个角色用浅底描边；不要让“学生”与“档口”等大，学生是弱侧；每条箭头必须带文字，空白箭头视为未完成

### 图3-1 备餐决策七步闭环

- **类型**：流程图（环形闭环）
- **内部模块**：7 个圆角矩形按顺时针排布（建档与准入→台账导入与核对→需求参考→约束与计划→执行确认→结果回填→周期复盘）；每个节点右上角挂一枚“产出物”小标签
- **数据流向**：单向顺时针；第 7 步“周期复盘”回到第 3 步“需求参考”，形成下一轮
- **标注文字**：节点内为动作名；产出物标签为“数据字典／清洗台账／区间／计划单／确认记录／实际结果／复盘报告”；第 5 步旁标“人工确认”
- **箭头逻辑**：主环实线；回环用一条外侧弧线并加“下一周期”字样；不得出现双向箭头
- **绘图重点**：7 个节点必须等大等距；回环弧线走外侧、避免穿过节点；把“人工确认”做成与流程并列的旁注，而不是流程中的必经方框

### 图3-4 成本临界比与约束投影

- **类型**：推导＋裁剪框图（上下两段）
- **内部模块**：上半段为成本参数（售价 p=13.0、单位成本 c=5.2、剩余净损失 o=1.30、缺货损失 l=10.14 四段），右侧给出临界比 ρ=l/(l+o)=10.14/11.44=0.886；中段为区间带（64—97）上取 ρ 分位得到建议量 100；下半段为计划量与首批／补餐条（额度→首批 82＋补餐 18）
- **数据流向**：成本参数→临界比→在区间上取分位→建议量→逐条裁剪→计划量（首批 82＋补餐 18）；被裁掉的部分向右下引出“缺口”
- **标注文字**：ρ=0.886；区间 64—97；建议 100；首批 82；补餐 18；缺口“不等于缺货”
- **箭头逻辑**：自上而下为主流程；裁剪用“剪刀”式反向箭头，表示数量被削减；缺口用红色虚线引出，与主流程分离
- **绘图重点**：这是全篇最核心的一张图，务必让“区间→分位→裁剪”三段一眼可读；数字化标注必须与正文一致；缺口与缺货的区分要用红色注释强调，避免读者混淆

### 图3-6 预测偏差与执行偏差的区分口径

- **类型**：数轴示意图（一维对照）
- **内部模块**：一条水平数轴，四个标记点（预测值、已确认计划、实际制作量、实际售出）；上方括注“预测偏差＝实际售出−预测”；下方括注“执行偏差＝实际制作−计划”
- **数据流向**：无流程方向，只有位置关系；右侧分支说明“供给受限时实际售出≠需求”
- **标注文字**：四个点名称；两个偏差公式；右下“供给受限”提示框
- **箭头逻辑**：用两条横向双箭头分别表示两种偏差的跨度，颜色不同（预测偏差用辅色、执行偏差用主色）
- **绘图重点**：四个点的高低顺序要符合示例数据；两条括注不能交叉；必须在图内出现“供给受限”的例外分支，否则会被误读为绝对值比较

### 图4-1 从台账到备餐建议的数据流

- **类型**：数据流图（五段横向）
- **内部模块**：台账→特征→模型→区间→决策；每段上方标输入、下方标产出物文件名
- **数据流向**：严格自左向右；每段之间用箭头，段内用竖向小箭头表示“处理”
- **标注文字**：段名（台账／特征／模型／区间／决策）；产出物（CSV／parquet／model.joblib／metrics.json／decision record）；顶部“失败即降级”旁支
- **箭头逻辑**：主链实线；降级路径用虚线从“模型”直接连到“决策”，并标注“退回规则基线”
- **绘图重点**：把“文件名”作为视觉锚点，让读者看到每一步都有可打开的产物；降级虚线不要穿过其他框；五段宽度可以不等，但基线必须对齐

### 图4-2 三档引擎、清单门禁与决策证据链

- **类型**：架构图（离线／门禁／在线／回路）
- **内部模块**：左上离线流水线（训练→分位→校准→指标 JSON→manifest）；中间门禁菱形判定（校验类型、哈希、版本）；右上三引擎并列（calibrated-quantile／quantile／rule）；下方证据链回路（写决策记录→重放重算→逐字段比对→一致／差异）
- **数据流向**：离线产物→门禁→通过则启用校准引擎、拒绝则退回 rule→输出建议；证据链单向记录、事后反向重算
- **标注文字**：“通过”“拒绝”“不做静默降级”“modelVersion 2026.10.27-interval-v1”“calibrationMethod cqr+stratified-aci”
- **箭头逻辑**：门禁两条出边（绿实线通过、红实线拒绝）；证据链回路用反向箭头，表示“用当前产物重算旧记录”
- **绘图重点**：门禁必须画成判定节点而不是普通方框；两条出边视觉权重相同，体现“降级是正常路径”；三引擎并列时把默认档加粗或加“默认”标签

### 图4-3 未校准／全局校准／分层校准区间对比

- **类型**：分布对比图（密度曲线＋区间带）
- **内部模块**：横轴“标准化销量”，纵轴“密度”；一组测试样本的真实值散点；三条区间带（未校准／全局 CQR／分层 CQR）横向并列；右侧小表给三组 PICP／PINAW／Winkler
- **数据流向**：无流程；用“真实值是否落入区间”表达覆盖
- **标注文字**：三组方法名；覆盖率 57.7%／97.4%／96.7%；宽度 0.1278／0.2966／0.2844；Winkler 29.87／19.75／19.01
- **箭头逻辑**：每条区间带用一对端点括号表示上下界；用竖向细线把真实值连到区间，落入为实线、落空为红色短横
- **绘图重点**：必须让“未校准区间明显窄且覆盖不住”这一事实一眼可见；数字只放右侧小表，不要贴在图线上；三条带的高度要留出呼吸空间

### 图4-4 系统分层架构

- **类型**：分层架构图（四层＋侧栏）
- **内部模块**：自上而下 表现层（Vue 3 SPA，/app/**，含证据页）／接口层（Spring Boot，/api/v1，鉴权与留痕）／模型层（三引擎＋清单门禁）／数据层（H2／MySQL，Flyway 迁移）；左上独立框“离线训练与产物导出”；右侧竖排 profile 标签（local／local-persistent／mysql）
- **数据流向**：表现层↔接口层（HTTPS/JSON）；接口层→模型层（调用）；模型层→数据层（读写）；离线产物以“产物＋manifest”箭头进入模型层
- **标注文字**：各层技术栈与端口 8089；“单一可部署包”；“Flyway 迁移失败即中止启动”
- **箭头逻辑**：层间双向箭头（请求/响应）；离线框用单向箭头指向模型层，表示只进不出
- **绘图重点**：四层高度自上而下递减或等分，不要画成五个不等高的条；profile 标签放在右侧竖排，避免与层内文字抢空间；端口号只出现一次

### 图5-1 七种区间方法覆盖率与宽度对照

- **类型**：柱线组合图（双纵轴）
- **内部模块**：横轴 7 种方法；左纵轴 PICP（%）；右纵轴 PINAW；柱形＝PICP，折线＋标记＝PINAW；Winkler 用第二组标记或数据表
- **数据流向**：数据来自 `interval_backtest_metrics.json`，只读呈现
- **标注文字**：90% 名义覆盖率水平虚线；四个关键值（57.7／96.7／97.4／92.6）；图注注明测试集 390 条
- **箭头逻辑**：无箭头；用水平虚线与“名义线”文字建立参照
- **绘图重点**：柱与线不要互相遮挡；把“未校准”一组用强调色，其余用中性色；纵轴不要从 0 开始截断到误导程度，需在图注说明起点

### 图5-2 决策策略 regret 与期望损失对照

- **类型**：分组柱状图
- **内部模块**：横轴 4 组策略（规则基线／未校准分位／校准后／批量取整）；每组 2 根柱（regret %、每百份期望损失元）；右侧注释差值
- **数据流向**：数据来自 `decision_backtest_metrics.json`
