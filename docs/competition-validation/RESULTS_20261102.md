## 核心发现：保留不利结果

| 情景 | 惯性 regret/100 | 固定 +10% regret/100 | 残差分位策略 regret/100 |
|---|---:|---:|---:|
| 基线 | 53.495 | **48.489** | 68.857 |
| 校园活动假设 | 53.307 | **48.219** | 69.438 |
| 雨天缩放 | 54.735 | **49.018** | 70.081 |
| 高波动压力测试 | 95.016 | **88.480** | 124.791 |

基线情景：固定 +10% 的缺货率为 26.5%，残差分位策略为 50.7%。后者剩余率更低（2.48% vs 4.36%），但主要原因是备餐更保守、缺货更多，不能把“剩余下降”单独宣传为改善。高波动时残差分位策略进一步退化。

这组结果只比较当前仿真生成过程中的三个策略，不说明固定 +10% 在所有真实食堂都最优。也不能把新实验策略等同于网站中所有已存在的模型实现：本入口是独立的观察受限策略回放。

## 与旧仿真器的差别

旧仿真器 `45_simulate.py` 在逐步决策时把仿真需求真值用于历史更新。现场售罄时只能观测到销售下限，这种做法会使后续策略获得现实中无法直接观测的真值。本轮不覆盖旧产物，而是新增 `51_competition_validation.py`：只使用此前可见售出量，并排除售罄日的残差校准。新增防泄漏测试验证“修改未来真值不改写过去建议”。

局限：排除售罄日仍可能留下选择偏差，尚未实现正式的删失需求估计。对此不能以扩大残差或反复调参制造优势；后续应在 FreshRetailNet 的缺货标记上单独验证删失处理方法。

## 单位与数据契约

新增纯函数支持份、个、公斤、升，以及显式提供抽样折算因子的锅/批次。单位量纲保持分离，不把公斤或升自动等同于份数。数量校验会拒绝负数、非有限数和未解释的差额。这是离线验证能力，尚未接入网页和 Java 业务接口，不能宣称网站已支持多单位经营台账。芬兰数据仅作为外部浪费量级参照，没有直接注入当前仿真生成参数。

## 建议的比赛选择

1. 默认基线继续选择易解释、易手工复核的方法；模型候选必须在固定切分和成本口径下胜出后才讨论上线。
2. 同时展示剩余、缺货和 regret；不能通过少做餐获得较低剩余后宣称减损。
3. 把数据守恒、单位量纲、时点可见与预测回放作为工程亮点；如实展示模型不利结果。
4. 公开数据外部回测、校准仿真和本地工程验收分层报告，不声称中国校园成效。
