# 校园餐饮可信备餐决策闭环落地方案

版本：2026-10-15  
项目：食刻有数（河北赛区校赛落地准备）

## 1. 落地目标

将“录入台账—生成备餐建议—现场执行—剩余处理—闭餐回填—复盘更新”做成可追溯闭环。系统输出的是经营辅助建议，不替代现场负责人、库存盘点和食品安全判断。演示数据、公开数据和真实河北台账分开标注，只有真实台账完成授权、来源和时间可用性核验后，才进入校园模型训练和成效结论。

## 2. 用户流程

### 首次使用

1. 管理员建立学校、档口和菜品，统一菜品编号、计量单位和餐次。
2. 负责人上传历史台账，先预览，再查看缺字段、重复主键、单位不一致、数量不守恒和来源未声明提示。
3. 通过检查的记录进入观察库；隔离记录保留原行号和原因，不能静默补零或覆盖。
4. 历史记录不足时，平台允许查看演示流程，但明确提示不能生成可信的校园模型结果。

### 每日营业

1. 营业前输入目标日期、餐次、菜品、预计天气、考试周/校园活动，并核对库存和产能。
2. 平台展示数据截止时间、模型版本、历史样本数和建议依据。
3. 输出需求范围、首批制作量、补餐量、参考停做时间和售罄/剩余风险。
4. 负责人选择采用或调整建议；调整必须记录数量、操作人和原因。
5. 营业中按实际库存和销售更新是否满足补餐条件；优惠操作必须再次确认食品安全。
6. 闭餐后回填实际备餐、售出、优惠售出、剩余、收入、缺货/停做和异常说明。

## 3. 数据准入与来源

每条观察记录保留 `school_id/stall_id/dish_id/business_date/meal_period/observation_id`、单位、标签来源、授权声明、原文件哈希、原始行号、来源登记 ID、`available_at`、`revision_at`。预测输入保留 `prediction_cutoff_at` 和来源登记。未知值保持缺失；停业、缺货、退款和修订分别标记，不把它们当作正常零销量。当前网页导入会自动登记文件 SHA-256 和声明字段，但状态为 `DECLARED_UNVERIFIED`，必须由数据负责人核验原文件和授权后才能进入真实训练。

同一实体和营业日的重复修订按“预测截止时点可见的最新版本”回放。本协议中 available_at 表示项目首次可用时间，revision_at 表示项目记录该版本的修订时间，因此 revision_at 不得早于 available_at；外部原文件的编辑时间不能直接充当 revision_at。时间缺失、非法或任一时间晚于预测截止时点的版本不能进入该时点特征。严格回放已通过脚本26的 build_replay_features 接入离线训练入口；缺少预测快照时不能宣称已回放。

## 4. 模型与区间

当前本地 LightGBM 文件是派生目标演示模型，不能写成河北校园销量模型。模型与特征文件通过 SHA256 清单绑定；校准文件若存在，必须同时声明并匹配模型和特征哈希，缺失绑定或错误搭配直接拒绝。2026-10-15 生成的 `local_model_bundle_20261015_safe` 不含未经校园独立校准的公开区间文件。旧的 `local_model_bundle_20261014` 含未经校园绑定核验的校准文件，仅保留历史审计，不得用于新上线。

真实校园训练必须按时间顺序冻结 fit/tune/calibration/test，逐预测时点执行可用性回放，并单独评价供给受限记录。独立校准集只用于拟合区间半径；最终测试集只用于一次报告。报告同时给出 MAE、缺货/剩余代价、区间覆盖率和区间宽度，不能只报有利指标。

## 5. 验收门槛

- 数据：准入报告有输入哈希、通过/隔离行数、原因分布；人工核验原文件和授权。
- 回放：未来修订不进入历史预测；缺失或非法时间拒绝；重复修订结果确定。
- 模型包：启动清单哈希匹配；校准模型/特征不匹配时构建失败；无独立校准时明确无有效覆盖声明。
- 用户：能够完成建档、CSV预览、生成建议、回填和复盘；数量守恒和食品安全确认阻止无效提交。
- 研究：保存切分、种子、配置、预测、指标、脚本哈希和运行日志；真实河北数据缺失时不输出现场成效。

## 6. 当前交付边界

已落地：离线逐预测时点回放、修订版本准入、模型包校准绑定、无误配校准的本地模型包、营业前执行计划确认、关联预测的闭餐回填、逐次预测/执行偏差复盘，以及测试与本方案。现有网页已具备台账录入、备餐建议、优惠、核销、预警和复盘入口。

边界：网页已新增应用层追加式修订库，按营业日与UTC微秒截止时刻选取版本；历史存量仅从首次捕获时起可用。预测计算、响应与存档使用同一批冻结版本，未版本化的动态反馈系数不参与该预测。事务内写入先取得单调发布水位，预测边界同时冻结已提交水位和观测时间；并发写入在 H2 场景已通过“未提交不可见、提交后新预测可见、旧回放不变”测试。该水位是应用写入层的提交快照证据，不等于数据库管理员不可篡改证明，也不覆盖原文件来源证据。脚本26已具备候选训练、独立校准和测试产物生成，但仍不是获得真实校园来源核验、Python-Java特征一致性和生产批准的校园模型流水线。当前默认本地环境使用内存数据库，重启不能作为持久化验收。

待外部条件满足后执行：河北学校/档口授权、原始台账、字段确认、连续采集、独立校准、影子运行和现场对照。上述事项不能用演示数据替代，也不自动上传、部署或推送。

建议从1所学校、2个档口、6—10道稳定售卖菜品、午餐单餐次开始。数量是试点设计建议，尚未取得任何学校或档口承诺。先统一份数、退单、赠送、报损和售罄口径，再扩大范围。

| 档口负责人 | 核对菜品、每天确认计划、闭餐盘点 | 菜品清单、每日台账、调整原因 |
| 数据负责人 | 留存原文件、计算哈希、登记版本并处理隔离记录 | 来源登记、准入报告、问题清单 |

## 9. 实施节奏与验收节点

以下以取得学校/档口授权为第0周，预计8—12周；有效样本、独立日期或现场条件不足时顺延，不能用排期代替科学验收。

| 阶段 | 工作与产物 | 进入下一阶段的门槛 |
|---|---|---|
| 第0周：范围确认 | 固定学校、档口、菜品、餐次、角色、数据用途；留存原始文件和授权引用 | 原始资料可核对，学校/档口确认参与，不包含不必要的学生个人信息 |
| 第1周：部署准备 | 补齐学校/档口建档、现场参数；独立数据库、账号、备份恢复；确定CSV转换口径 | 测试库与真实库隔离；重启数据保留、备份恢复、权限和人工降级通过 |
| 第2—6周：连续采集 | 记录实际结果与预测输入快照，保留首次可用与每次修订；每天检查缺货、缺失和数量平衡 | 拟议完整率≥95%；全部拒绝项有人处理；覆盖至少28个自然日的历史窗口且有效样本足够 |
| 第7—8周：离线与影子运行 | 冻结切分、基线和候选；平台生成建议但不自动执行 | 独立校准/测试没有泄漏；候选优于简单基线且关键组无明显退化，否则保留基线 |
| 第9—12周：小范围现场验证 | 经现场方批准后开展对照；记录是否采用、原因、缺货与剩余；访谈使用负担 | 经营成本和服务水平按预设标准评价；失败和不利结果同样保留 |

“完整率≥95%”是拟议运营门槛，不是已取得结果。100条训练行数只是脚本的最低工程检查，不能证明样本量充足。实际试点需要依据营业日相关性、菜品差异和效应目标确定样本量，不能把菜品×天当成完全独立样本。

## 10. 模型比较与上线决策

1. 先固定时点、单位、数据集与时间切分，再比较同星期均值、滚动均值/EWMA、LightGBM和残差修正模型。各模型使用同一批预测时点，不能把公开缩放销量和校园份数混比。
2. 只在 fit/tune 比较特征和超参数。校准集估计区间半径；test 不选模型。已看过的公开后段只能写作探索结果。
3. 主指标为份数MAE与按真实成本定义的缺货/剩余损失，同时报告分菜品误差、偏差、冷启动降级、区间覆盖与宽度。售罄后的观测销量不等于需求，供给受限样本单列。
4. 区间采用有限样本残差次序统计量；样本数不足以支持目标覆盖水平时拒绝输出半径。时间漂移会破坏覆盖假设，不能承诺未来覆盖概率。
5. 模型先保存在服务器本机并启动加载；预测请求不重训、不重新下载模型。大模型用于解释和检索可追溯材料，数量由可验证算法给出，外部AI失败时保留规则建议。
6. 加载速度不能代替预测准确性；是否更快要实测启动时间、冷/热请求p50/p95和内存。当前不宣称已完成生产性能压测。
7. 候选、特征、校准、来源、切分与哈希成套归档。通过 Python/Java 特征与预测对照、重启、影子运行和现场批准后，才人工切换；保留上一稳定版本及回退步骤。

## 11. 现场评价与竞赛证据

把“能使用”“预测有效”“经营改善”分开验收：

- 能使用：操作人可在帮助页指引下完成一次确认—回填；记录耗时、出错与拒绝原因，不用开发人员代操作作为唯一证据。
- 预测有效：固定未来时段评测，比较简单基线和候选；保存每次预测及真实结果，不能事后挑选最好的那次预测。
- 经营改善：先进行影子运行，再由现场方批准对照方案；按档口/营业日考虑分组和时间相关性，同时看缺货、剩余成本、收入和备餐工作量。未经合理对照只能描述同期变化，不能声称因果收益。
- 竞赛材料：准备授权脱敏件、来源与口径表、原始文件哈希、数据质量图、时间切分图、模型对比与不利分组、区间图、用户流程图、界面截图和现场验证记录。演示截图明确标注演示环境。

建议主张围绕“预测时点可追溯的数据、分批备餐和人工执行复盘”组织；算法新颖性与可复现证据未确认前，不宣称首创、论文级成果或行业领先。

## 13. 候选训练链增量

训练脚本现已从“仅回放和基线”扩展为可复现的候选评估链：先按每个预测截止时点筛选可见修订，再按日期冻结 fit/tune/calibration/test；仅用 tune 选择星期基线或受限 LightGBM-L1，使用独立 calibration 计算有限样本绝对残差区间，在 test 上只做一次报告。运行结果保存切分清单、校准预测、测试预测、候选模型或基线参数、特征文件和带模型/特征 SHA-256 的 `calibration.json`；同时报告测试集区间覆盖率和平均区间宽度。命令行集成测试已验证这些文件实际落盘且绑定可复核。

链条仍返回 `training_ready=false`，因为来源人工核验、实体留出、Python-Java 特征一致性和现场批准属于独立门槛；短校准集、校准标签在测试起点后才可用等情况会直接拒绝。

## 14. 来源证据链落地补充

CSV导入现已要求来源名称、提供方、声明地域和授权引用，自动计算文件SHA-256，并将来源登记ID、原始行号关联到台账修订与预测快照。历史回放核对来源是否一致，来源被修改时拒绝回放。本轮Java全量38项通过，含该拒绝场景和来源登记只读接口测试。
来源登记还提供只读核对接口 `/api/v1/operations/source-evidence`，CSV导入页可展开查看最近登记的文件指纹、声明范围、授权引用和待核验状态。

第6、12节所列来源关联工程已完成；原始文件保管与人工授权/地域核验仍待执行。所有当前登记均为声明待核验，不据此放开真实校园训练或宣称河北现场数据可信。文件型H2重启验证已通过，生产数据库备份恢复仍待验收。
