# 经营数据导入说明

在“经营记录”页面选择“数据批量导入”，上传经营数据文件，先预览字段和样例，再填写来源及记录人并确认导入。

## 支持格式

| 格式 | 组织方式 |
| --- | --- |
| Excel（.xlsx、.xls） | 第一个非空工作表，首个非空行作为表头；每行一条记录。预览显示实际工作表名称。日期和数值单元格直接识别，公式须转为值。 |
| CSV | 首行为表头，逗号分隔，支持引号、引号内逗号和换行。 |
| TSV | 首行为表头，制表符分隔。 |
| JSON | 对象数组，或形如 `{"records": [...]}` 的对象；每个对象对应一条记录，字段值为文本、数字、布尔值或null。 |

每次最多10MB、10000条记录、100列。CSV/TSV支持UTF-8（含BOM）及GB18030编码。Excel仅导入第一个非空工作表，其他工作表请分别上传。预览列出最多20条样例和解析记录总数；“表头齐全”仅说明字段齐全，正式导入仍逐行校验经营数据。

## 字段

| 英文字段 | 支持的中文列名 | 内容 |
| --- | --- | --- |
| business_date | 营业日期、日期 | YYYY-MM-DD；Excel日期单元格也可识别 |
| dish_id | 菜品ID、菜品编号 | 已建档的菜品ID；菜名不自动匹配到ID |
| planned_qty | 建议备餐、计划备餐 | 非负整数 |
| prepared_qty | 实际备餐、制作数量 | 非负整数 |
| sold_qty | 售出、实际售出 | 非负整数，包含优惠售出 |
| discount_sold_qty | 优惠售出 | 非负整数，不超过总售出 |
| leftover_qty | 闭餐剩余、剩余 | 非负整数 |
| revenue | 收入、营业收入 | 按台账口径填写收入金额 |
| weather | 天气 | 当日天气记录 |
| meal_period（可选） | 餐次 | 早餐、午餐、晚餐等现有台账餐次；缺失时标为未标注 |
| event_tag（可选） | 现场情况 | 当餐活动或特殊情况 |
| recommendation_adopted（可选） | 是否采用建议 | true/false、是/否、1/0；缺失为false |

前九项为必填字段。同义列名映射后不允许重复。数量必须满足“实际备餐＝总售出＋剩余”，优惠售出是总售出的组成部分。仅改扩展名不会转换文件格式；非标准POS字段需要先整理为对应字段。当前没有直接连接POS、支付或校内系统的接口。

## JSON示例

以下为构造示例；菜品ID需要替换为已建档的真实ID。

```json
{
  "records": [
    {
      "business_date": "2026-11-09",
      "meal_period": "午餐",
      "dish_id": 1,
      "planned_qty": 100,
      "prepared_qty": 100,
      "sold_qty": 90,
      "discount_sold_qty": 10,
      "leftover_qty": 10,
      "revenue": 850,
      "weather": "晴",
      "recommendation_adopted": true
    }
  ]
}
```

## 导入结果与来源

确认前先检查数据样例、计量单位及来源。同一日期、餐次和菜品已有记录时会更新并保留台账修订；经营规则不合格的行会报告原因，其他合格行按原有流程处理。重复提交同一写请求由幂等键控制。

各格式保存原始文件的SHA-256、来源声明、导入批次和记录序号，供后续核对。来源声明不等于来源和授权已经核实。解析格式错误、重复字段、公式或超量文件在创建导入批次前拒绝；单行经营数据错误在导入结果中列出。JSON序号从1开始；CSV/TSV序号含表头记录，Excel序号为原工作表行号。

接口保持不变：`POST /api/v1/operations/import/preview` 用于预览，`POST /api/v1/operations/import` 用于确认，均采用multipart文件上传。所有格式共用原有来源声明、记录人、确认与幂等参数。
