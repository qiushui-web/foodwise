## 本轮已落地

现场约束计划已接入网页和后端：输入本菜品获分配的库存、产能、最小批量、提前期、准备时间和营业时段，计算首批、补餐、总量及缺口；保存预测关联、输入、输出、账号和时间，支持读回。零库存返回零计划，非法输入被拒绝，确认数量受到最近留档计划约束。该计划不会自动扣库存或发出制作命令。

独立试运行配置关闭演示经营种子，启用认证和文件持久化；已有停机备份、隔离恢复、读回校验和本机只读性能测量脚本。授权、原件登记、每日质量、用户任务观察、影子运行、冻结实验、现场验证和竞赛主张均有空模板。

本地模型已有模型文件、特征清单、哈希和 Java 加载校验入口；当前清单标记为 `derived-target-demonstration`，不能表述成河北真实校园训练模型。本地推理避免每次预测重新训练或远程下载模型，但实际预测延迟仍需专项测量。

## 已有验证

- Java：48 项测试通过；Python 模型链：41 项通过；前端类型检查、构建和 bootJar 通过。
- 浏览器：1440px、390px 主流程通过；无横向溢出、控制台错误或失败资源。
- 持久化：档口、菜品、订单、回填、计划、预测回放在重启及隔离恢复后读回一致。
- 备份：源文件与恢复文件 SHA-256 一致；恢复未覆盖原库。
- 性能：本机顺序认证 GET 的 p50 约 64.7—70.2ms、p95 约 79.7—82.0ms；不属于预测延迟或线上并发结果。

以上业务流程验收均使用隔离构造数据。详细日志、失败排查历史和最终 JSON 保留在验收目录，不把早期失败日志当作最终结果，也不删除失败证据。

## 下一次现场启动的最小输入包

准备一份授权引用、一张档口与菜品清单、一份脱敏原始台账及其字段说明、一名现场负责人。先做字段映射和影子运行，再决定训练与经营干预。7—14 天可用于演示或初期核对，不是训练充分性标准；实际是否足够取决于餐次覆盖、异常、季节变化、切分和独立确认要求。
