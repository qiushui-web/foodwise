# 食刻有数：数据与模型优化实施方案

日期：2026-10-13。状态：目标模式active；已完成首轮内部时间窗、残差对照、组消融、融合与残差区间实验，详见OPTIMIZATION_RESULTS_20261013.md。真实校园验证尚未完成。当前授权为本地方案、数据审计和可行实验；不自动上传数据、下载未核准数据、推送、部署或替换线上模型。保护已有工作区改动。

## 1. 目标与当前基准

目标是建立可追溯、可复现、能够公平比较且满足档口操作约束的预测流程。允许简单基线胜出，不以一定训练出更强LightGBM作为成功条件。

当前依据：src/main/resources/modeling/MODEL_CARD.md、public_sales_report.json、modeling/scripts/14_public_sales_validation.py、03_output下公开销量实验及审计报告。

| 路线 | 当前证据 | 处理 |
|---|---|---|
| 线上24维校园LightGBM | 训练销量来自浪费观测派生；校园销量精度未成立 | 保留演示标签，不作为生产模型候选 |
| 14天98条台账 | simulation，简单7日均值优于小样本LightGBM | 仅用于流程、接口和测试 |
| public-sales-v2 | 独立缩放销量实验，按时间训练/调参/校准/测试 | 作为方法研究基准；不转为份数和收益 |
| 最新公开测试 | 四周同星期MAE约0.230；LightGBM约0.308 | 不重复挑选该测试集；新优化使用训练期内部验证 |

注意：已阅读过的2023年测试集已经成为探索证据，不能再作为新方案的全新独立确认测试。不得用反复调参后的同一测试结果宣传无偏泛化能力。

第二轮详见OPTIMIZATION_ROUND2_20261013.md。留店、EWMA、L1/L2及区间比较已执行；门控早期留店不利、后段探索有利，未认证通用回退。旧导出行切分与匹配元数据日期重叠，不支持严格时间回测；生成链仍缺，不替换线上模型。

## 2. 数据集优化：准入与角色

### 2.1 每份数据建立来源卡

记录source_id、原始链接、发布者、取得日期、许可证文本、授权范围、字段与单位、地域、时间粒度、实体粒度、时间范围、缺失日期、标签生成方式、文件SHA256、清洗版本。状态分：已核验、供应方声明、未核验。许可证允许使用与来源真实是两件事。

| 数据 | 允许用途 | 准入检查 | 禁止用途 |
|---|---|---|---|
| university_food_waste | 浪费重量分析、字段与页面演示 | 来源机构、采样方法、时间范围、重量/价格单位 | 从浪费反推销量后称真实销量标签 |
| gylaf校园交易 | 授权且许可允许的日期/品类聚合销量 | 时间对齐、退款、交易量与份数关系；排除个人交易明细 | 将校园交易次数直接等同菜品需求 |
| food_demand | 周订单需求方法基准 | 中心/餐品/周键，订单定义，官方训练标签 | 周序号直接当日销量或校园日历 |
| 零售天气数据 | 来源核验后的天气/销量研究 | 天气取得时点、真实销量字段及采样说明 | 仅凭文件名或CC0宣称真实实测 |
| Reduce Foodwaste | 独立缩放销量方法研究 | 来源README、缩放方法、日期/店铺完整性 | 转为份数、金额、食品剩余率 |
| 仿真台账 | 业务管线测试 | simulation标记贯穿导入、报告和展示 | 实地减损、收入、付费成果 |
| 河北授权台账 | 校园生产候选训练和现场验证 | 原始POS/手工来源、授权、餐次、单位、缺货记录 | 未经授权上传或含个人身份的训练 |

多源数据先单独建模。只有目标单位、时间粒度、实体定义、特征可用时点对齐后，才研究跨域模型；必须比较本地从零训练、源域模型直接迁移和迁移微调，负迁移则拒绝。大规模总行数不证明模型有效。

### 2.2 河北采集设计

建议先2—3档口、每档口3—5个稳定菜品，连续8—12周；这是可执行采集目标，不是统计功效结论。单档口先做可用性试点，不能推断跨校有效。跨校泛化需新增独立学校验证。

预测单位：学校×档口×菜品×营业日期×餐次。第一阶段预测次餐售出量；未记录缺货前不称完整需求量。记录订单份数，称重菜品另建重量目标，不混为同一标签。

| 字段组 | 字段 | 采集方/时点 |
|---|---|---|
| 主键 | school_id, stall_id, dish_id, business_date, meal_period | 管理员建档，稳定ID |
| 菜品 | dish_name, category, unit, price, unit_cost | 建档；价格变更保留生效时点 |
| 库存流 | opening_qty, prepared_qty, transfer_in_qty, transfer_out_qty, returned_qty, discarded_qty, closing_qty | 开/闭餐或批次回传 |
| 销售 | sold_regular_qty, sold_discount_qty, refund_qty, revenue | POS导入，统一退款口径 |
| 可售条件 | open_time, close_time, stockout_time, unavailable_minutes | 缺货时补记；停业不当零需求 |
| 预测场景 | forecast_weather, forecast_issued_at, exam_flag, event_flag, promotion_plan | 预测截止前可得 |
| 执行动作 | prediction_id, recommendation_qty, adopted_flag, actual_plan_qty, override_reason | 负责人确认；不作当次预测输入 |
| 来源与质量 | source_id, imported_at, label_origin, quality_flags | 系统留痕 |

库存守恒按事件定义：期初+制作+调入=净售出+调出+退回厨房+报损+期末。优惠售出是总售出的子项或独立销售项，两种模式选一并全链一致，禁止重复扣减。缺货未满足需求不能随意补成假销量。

用户负担：一次准备菜品清单、最近台账、POS导出和授权；每天确认校历/活动异常、建议执行量；闭餐只补剩余、报损、缺货和调整原因。POS自动对接未验收前提供CSV路径，不能说已经自动同步。

### 2.3 清洗和准入规则

- 主键重复先追溯退款/修正版本，禁止随意求平均；保留原始层，只向清洗层写入。
- 缺失日期区分停业、漏报、零销量；未知不填0。日历重索引后lag7按日历计算。
- 单位冲突、非法日期、缺少来源、守恒不符记录隔离，不静默丢弃；报告分母和剔除比例。
- 异常高销量先保留标记，核实活动/团购；不能把困难样本删掉来提升误差。
- 天气使用预测时已发布的预报；事后实际天气只供复盘。活动以提前知悉信息为准。
- 动态质量阈值先由采集试运行确定，冻结后验收。建议候选门槛：关键字段完整率≥95%、已入模守恒通过率100%、未解释主键重复0；这些是工程目标，不是当前结果。

## 3. 验证协议优化

### 3.1 预测截止与切分

固定次餐预测截止时间，例如前一日20:00（待档口确认），输入必须在该时点可用。当天最终销量、当天剩余、事后天气、建议采纳结果不得入当次特征。

公开实验：使用原train期内部3个扩展窗口选择配置，原tune期只做一次模型选择，原calibration只做区间校准。原test期已经看过，继续结果标探索性。确认性结论需要新的时间尾段或新实体来源；数据不足则明确未确认。

校园实验：训练/验证/校准/最终测试按日期成块，所有菜品同日同区，不能逐行随机划分。建议至少保留最后2周最终测试和之前2周校准，前期做3个扩展回测窗口；短于该周期只做探索，不强行按比例得出强结论。所有清洗统计、编码、标准化在训练窗拟合。

增加留一档口验证评估冷启动；新学校必须单独验证。跨餐次同日特征根据截止时点判断可用性。缺货期单独报告受限销量误差，不将其当潜在需求真值。

### 3.2 冻结基线与指标

候选基线：昨日、上周同日、四周同星期均值、最近7日均值、EWMA、季节性均值加趋势（仅在内部验证后入选）。缺历史时采用菜品/餐次组均值并披露低数据状态。

真实份数：主指标MAE(份)和WAPE，辅以偏差、sMAPE、分餐次/菜品/档口指标。零销量单独报告；MAPE仅正标签子集且标分母，不作主宣传。缩放可负销量：MAE/RMSE和MASE（尺度只由训练集计算），WAPE仅作口径限定的辅助；不使用RMSLE和金额换算。

统计比较：保存同一日期实体配对误差，按周块重采样，跨档口同时考虑实体簇；样本不足不报强显著性。不能把上千行同店重复观测当上千独立样本。

## 4. 模型优化：先基线，再小模型，最后策略

### 4.1 实验顺序

| 实验 | 改动 | 目的 | 通过条件 |
|---|---|---|---|
| E00 | 冻结public-sales-v2报告/源哈希 | 保留失败也可追溯的基准 | 原结果可读取，版本明确 |
| E01 | 来源与日期/单位审计 | 先确认标签能否使用 | 原始、派生、仿真分层 |
| E02 | 训练期内3窗基线与现有LGBM比较 | 定位为何调参集和测试排序反转 | 保存每窗/每实体误差与漂移 |
| E03 | 核对标签缩放、实体分布和特征缺失 | 区分漂移与模型缺陷 | 未知缩放不逆变换 |
| E04 | 直接LGBM与季节性残差LGBM | 学基线解释不了的变化 | 同一验证窗比较，允许基线胜出 |
| E05 | 特征组消融 | 检验特征是否带来增益 | 无增益组删除，避免名词堆砌 |
| E06 | 全局、分实体、分餐次模型 | 找共享与异质性平衡 | 小实体不单独拟合复杂树 |
| E07 | 固定融合在内部窗选权重 | 替代无依据60/40 | 权重只在验证集选择并冻结 |
| E08 | 残差区间/分位数区间 | 给不确定性且约束宽度 | 独立校准，测试报告覆盖/宽度 |
| E09 | Python-Java输入与推理一致性 | 消除部署误差 | 特征值和输出均验收 |
| E10 | 真实档口影子运行 | 不干预先看预测和负担 | 完整记录人工计划及缺货 |
| E11 | 有对照的经营策略试点 | 验证少剩是否导致多缺 | 剩余/缺货/成本联合评估 |

### 4.2 LightGBM具体候选

第一轮控制预算：叶数7/15，min_child_samples20/50，learning_rate0.03/0.05，树数上限300，内部验证early stopping 30轮；先固定其余正则参数，不一次全网格。每条路线最多8个预登记候选，验证窗MAE优先、偏差和最差窗作约束。最终树数从内部验证确定，测试不调参。

残差路线：y=季节性基线+residual_model。基线必须只用过去数据；公开缩放标签允许负数，直接拟合残差，不用log1p。真实非负销量比较原尺度L1与log1p路线；反变换、截断和偏差必须在相同协议评估。是否Poisson取决于整数计数语义和目标非负，不能用于负缩放标签。

暂不增加LSTM/Transformer：当前瓶颈是来源、标签与时间漂移。只有简单/树模型已公平验证且有足够独立长序列时才进入深度模型阶段。

### 4.3 特征分层与冷启动

A组历史：lag1/2/3/7/14/28、仅过去的3/7/14/28日均值/中位数/波动、四周同星期均值；B组日历：星期、餐次、教学周、预先确认的考试/活动；C组经营：预测时已生效价格、成本、促销；D组天气：预报温度/降水；E组供给：营业计划、可售时段、容量。逐组增加，每组单独消融。

没有现场数据的考试/活动特征不生成假标签；缺失以unknown表达，固定0字段不宣传有效。目标编码仅训练期拟合。历史不足分三档：不足7天规则/组均值；7—27天短历史基线；满28天才启用四周季节性特征。档位只是候选门槛，须通过回测确定。

### 4.4 融合与模型选择

验证集比较alpha={0,0.25,0.5,0.75,1}的基线与ML组合，alpha=0完全允许。优先全局或数据充足的分餐次选择，避免每个小菜品挑不同权重过拟合。线上60/40只保留演示兼容，不宣称最优。

### 4.5 区间与经营策略

独立校准集比较绝对残差区间、按档口/餐次分组残差（样本不足回退全局）、LightGBM分位数加校准。报告80%/90%覆盖、宽度、分组覆盖及interval score；未来漂移不承诺严格覆盖。不能将公开缩放实验区间迁移到校园份数。

真实备餐策略用单份过量成本Co与缺货成本Cu决定分位数Cu/(Cu+Co)。成本需档口确认，剩余可折价回收时核算净成本。加入最小批次、制作周期、产能、售卖截止和人工确认。±8%与首批82%必须和固定策略基线比较，不直接当科学最优。缺货成本难观测时给敏感性范围，不虚构金额。

## 5. 现场实验与用户使用

先影子运行2周：系统计算但不要求采纳；记录人工计划、模型建议、最终销量、缺货和操作时间。随后采用可比档口簇的同期对照；按档口/周分组随机需场地方同意，不能在菜品之间任意随机造成共享库存和客流干扰。单档口前后对比标探索，控制星期、菜单、校历、活动和价格，不能自动得出因果减损。

主结果：剩余/报损数量或成本；约束结果：缺货、售罄时间、原价销售与毛利；使用结果：完整率、采纳率、输入耗时、人工覆写原因。连续重复观测不当独立档口。试点周期和簇数先根据影子期波动估算功效，8—12周不保证统计显著。

首次用户提供授权和菜品映射，上传CSV；开餐前补校历异常、查看建议、确认量；营业中按实际补餐并记录异常；闭餐补剩余/报损/缺货。系统后台构造特征和模型；大模型仅解释脱敏事实与旁路提示，不参与标签生成、数据真实性认证或模型评测裁判。

## 6. 上线门槛、回滚与交付

建议候选门槛（尚未达到）：相对冻结最佳基线整体MAE降低≥5%，多数时间窗不退化，关键菜品/档口无明显系统性偏差；证据不足保留基线，不能为了上线强换模型。最终阈值需在实验前与业务成本绑定。

Python-Java验收包括同一向量预测误差≤1e-6（浮点容差目标）、真实在线特征逐字段一致、缺失历史/缺天/跨餐次/零销量/日期切换、输出截断和逆变换；特征名称相同和文件哈希相同不能替代这些测试。

产物每次写入独立run_id目录：protocol.json、source_manifest.json、split_manifest.csv、config.json、metrics.json、predictions.csv、calibration.json、model.txt、环境依赖、耗时和日志。写candidate模型卡，不覆盖现有模型。上线前人工复核后再切版本；失败回规则/基线。记录输入分布、偏差、缺失率，满足预设漂移条件才再训练，训练后仍需同样验收。

## 7. 阶段安排和验收

投入优先级建议：40%用于真实标签与数据质量，25%用于时间/实体验证及漂移，20%用于特征、简单基线与小模型，10%用于部署一致性和经营约束，5%用于解释展示。比例是工作分配建议，不是比赛官方评分权重。先消除标签和验证错误，再决定是否值得增加模型复杂度。

| 阶段 | 建议工作量 | 产物 | 完成条件 |
|---|---|---|---|
| P0 | 本地1—2天 | 来源/目标/脚本产物审计、冻结协议 | 数据角色和可用边界明确 |
| P1 | 本地2—4天 | 内部窗基线、漂移、残差候选比较 | 可复现结果和失败分析俱全 |
| P2 | 本地1—2天 | 消融、区间、候选报告 | 不使用已看测试调优 |
| P3 | 现场8—12周采集目标 | 授权台账、质量报告 | 标签与单位通过准入 |
| P4 | 采集达标后 | 校园候选与部署一致性 | 时间/实体验证达标 |
| P5 | 现场批准后 | 影子运行和对照验证 | 预测、经营、使用证据分开 |

工作量为估计，非承诺期限。当地数据和场地方许可不由目标模式自动产生。目标模式先完成可自主推进的P0—P2；P3以后保持待采集/待现场批准，绝不伪造完成。
